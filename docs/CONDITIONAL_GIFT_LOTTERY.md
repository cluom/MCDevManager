# 条件抽奖与赠送 CSV

入口：互动管理 → 条件抽奖。不会自动赠送或扣费；自动回复默认关闭，只有用户填写文案并启用、且本轮全部当前中奖者被报告确认赠送成功后，才会公开回复源评论。

## 本次灵气复苏活动

当前账号作品中存在对应条目时，默认选中免费凡人问道来源组件 `4688538944207380371`、灵气复苏赠送组件 `4690141251535232006`，以及五星、抽取 200 人。默认日期为最近 30 天，可通过日历选择活动日期范围（北京时间，包含开始及结束当天）。

1. 从可搜索下拉框选择来源/赠送模组（显示名称与 ID，支持按两者搜索），点击起止日期打开日历，再选择评分；可添加评论类型、包含/排除关键词及明确的 UID 排除名单。作品列表加载失败可重试，账号切换后须重新选择模组。
2. 点击“读取完整评论并抽奖”。每 UID 在所选日期内只采用最新评价，再匹配条件，每人一张票；候选人数不足、缺页或读取失败时不出部分名单。
3. 核对中奖预览与种子，点击“导出新名单 CSV”。生成 UTF-8 BOM、CRLF、两列 `玩家uid,模组id`，所有 ID 都按字符串精确保留。
4. 将 CSV 直接导入平台。不要用 Excel 打开后另存，大整数 ID 可能被表格软件改写。
5. 平台赠送完成后，点击“导入赠送报告 CSV 并自动补抽”，选择平台导出的报告；也可以手动点击“已购，换人”，或将这些**当前中奖 UID**批量粘贴到补抽框。只更换明确失败或手动指定的名额，其他中奖者保持不变，当前及历史抽中 UID 不再入池。
6. 再点“导出新名单 CSV”，默认只包含尚未导出的新增补位玩家，不重复输出旧批次。候选池耗尽时明确报错，旧名单不发生部分修改。

“已导出”只表示文件保存成功，不代表赠送成功。若导出后尚未上传、文件丢失，或需要核对完整当前名单，可使用“重新导出完整名单”，并自行避免重复提交成功赠送的玩家。重新整组抽奖或修改条件会清空本轮历史，应先保存审计。

## 导入赠送报告

- 支持平台 UTF-8 CSV：必须包含 `玩家uid`（或明确的 `uid` / `game_uid`）、`模组id`、`状态`，可包含 `失败原因` 及其他价格/名称列。ID 全程按字符串处理；不会把订单 `玩家ID/app_uid` 当作 UID，也不会将文件上传服务器。
- 按当前赠送模组 ID 和当前中奖 UID 匹配。明确的“失败/赠送失败/发放失败”自动补抽；“成功/赠送成功/发放成功”保留并锁定，之后不能用旧失败报告或手动操作再次替换。其他语言的 success/succeeded/failed/failure 也可识别。
- 同一 UID 的重复失败只补一次；同份报告内成功优先。未知、空白或处理中状态不视为失败；如果同一 UID 同时有失败和待确认状态且没有成功，保留原名额。未出现在报告中的玩家不推断成功或失败。
- 报告中属于其他模组、非当前中奖名单的记录跳过并显示数量。重复导入旧失败报告不会再次替换新补位者。候选不足、报告列缺失或 ID 无效时整个导入失败，不部分修改原名单。
- 匹配当前名单的记录意味着这些名额已提交平台，不会再次进入默认的新名单 CSV；只有新补位及其他尚未导出的名额会输出。完整名单重导出仍仅用于恢复/核对。
- 必须在同一轮抽奖结果中导入。当前结果仍保存在内存里，旧报告本身没有完整候选池，不能用它恢复已经关闭的抽奖会话；请选择报告对应的当前名单，不要重新整组抽奖后期待恢复旧名额。

## 已购判断的边界

评论原始接口的 `uid` 和实时收益订单的 `app_uid`（订单 CSV 的“玩家ID”）尚未确认可靠映射，因此本功能不宣称已自动排除购买者。用户已选择“平台判定已购后补抽”的工作流。

排除名单仅接受明确的 `玩家uid`、`uid` 或 `game_uid` 列；支持 UTF-8 CSV 的引号、多行备注以及去重。订单表、仅昵称表、科学计数法或公式形式 ID 均拒绝直接导入。手动粘贴 UID 可用逗号或换行分隔。

## 全部报告确认后的自动回复

1. 抽奖结果内找到“全部赠送确认后，自动回复源评论”，填写自定义文案，核对预览。支持 `{昵称}`、`{赠送模组}`、`{模组ID}`，每条展开后限制 1～500 字符（本地限制，不代表官方上限）。
2. 开启“自动公开回复”。如果报告还未齐全，保持等待；如果已经全部确认成功，开启后立即核对并处理本轮源评论。修改文案会关闭开关，需要再次核对启用。
3. 分批导入赠送报告。**须当前全部中奖 UID 都被明确成功报告覆盖**才发送，失败后新补位者也须有成功报告；已导出、部分成功、待处理或手动补抽均不能提前触发。
4. 回复前重新读取并核对抽奖依据的原评论 ID、UID、来源模组；已有回复、已删除或身份不匹配时跳过。按名单顺序串行发送，间隔 1.5 秒；可查看总进度与逐人通知状态，也可停止。
5. 同一账号和源评论的发送状态保存在本机，成功不重复发送，改文案不会覆盖已成功的通知。超时、取消等不确定请求保留“待核对”而不自动重发；可去普通评论管理中人工核对。平台明确拒绝时批次停止，解决问题后点击“继续未发送项 / 重试明确失败项”。

自动回复使用启用时账号的独立 Cookie 快照，切换账号会取消后续请求，不会改用另一账号继续旧任务；已在网络中的请求仍可能完成，状态会按原账号记录。预检和回复不是服务端原子事务，请不要同时人工修改这些回复或在多个客户端执行批量通知。

无需数据库升级。发送记录采用平台本地首选项（Windows 为当前用户首选项），不保存 Cookie；抽奖审计包含本轮回复状态与文案。此处只持久保存发送去重状态，**并不恢复关闭客户端后的整个抽奖会话**。

## 完整性与账号安全

- API 结束日为排他边界；界面自动请求下一日，保证界面所选结束日被包含。
- count 达到 9999 时按日期拆分，再分页读取；单日仍封顶、总数变化、重复页或缺页均停止。不保证第三方远端数据在并发编辑时具有数据库级原子快照。
- 参数变更、取消或账号切换会废弃旧任务与结果。账号切换同时清空旧排除名单；文件保存前再次核对账号与结果快照。
- CSV 和审计只在用户选择的位置保存。审计包含条件、固定算法、种子、候选/中奖 UID、依据评论 ID、补抽和导出记录，不包含 Cookie 或密码。请按玩家数据保管，不要提交到公开仓库。
- 结果目前保存在页面 ViewModel 的内存中，关闭客户端后不保证恢复；需要留档时先保存审计 JSON。本轮不提供审计导入恢复功能。
