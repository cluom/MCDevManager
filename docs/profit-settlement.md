# 收益速算与官方月账单

## 数据来源

收益速算通过现有 `IncomeRepository.getIncome("all")` 读取 `incomes`，仅使用 `platform=pe` 的账单，与首页 PE 模组及联机大厅流水对应。只读获取，不发起提现或其他平台写操作。

- `total_diamond`、`adjust_diamond`、`channel_ip_cost`、`sharable_flow`、`developer_share`：钻石。
- `exchange_rate`：钻石兑换人民币的系数。
- `income`、`incentive_income`、`tax`、`tech_service_fee`、`total_usage_price`：人民币。
- `available_income` 可能累积多个月份，不能用作某个月的收益。

## 计算规则

1. 按 `data_month` 匹配当月官方账单，不按接口返回顺序或提现状态选择。
2. 已出账：开发者分成直接使用 `developer_share × exchange_rate`，总收益直接使用 `income`，净收益使用 `income - tax - tech_service_fee - total_usage_price`。不以估算公式覆盖官方税费、激励或舍入差异。
3. 未出账：优先取上月有效账单；没有上月账单则取最近的更早账单，并显示来源月份。不得使用未来月份。
4. 生态费率为 `channel_ip_cost / (total_diamond + adjust_diamond)`。计算前校验 `channel_ip_cost + sharable_flow` 与该总流水相符（容差 0.02 钻石），以及数值有限、非负、分母大于零。
5. 预估开发者分成继续按当前各模组流水分档计算（50%、52.5%、55%），统一使用历史账单得到的可分成比例；既有激励与退款周期规则不变。
6. 接口失败、缺字段、重复月账单或无有效历史费率时，不回退到固定 30%/35%/36%，而是保留流水，显示收益暂不可估算。

## 模组明细与人员分账

月账单只提供总账，不包含逐模组真实生态费或真实结算明细。因此已出账月份的模组明细仍是估算权重，界面明确标注，不能称作官方逐模组结算。

人员分账使用官方净收益作为总池，按现有模组估算权重及人员归属分配。不重复扣税，不重新推算总池。若逐模组流水合计与官方总流水不一致（容差 0.02 钻石），不将差额擅自分摊给已知模组，全部保留为未分配，等待核对。

## 存储与验证

无手动费率输入、无费率设置存储、无数据库迁移；只扩展接口解析与内存计算。进入收益详情会重新核对账单，避免始终使用账单发布前的首页缓存。

`SettlementProfitTest` 覆盖字段解析、真实费率、已出账与未出账、跨年、平台过滤、重复与缺失账单、分成档位、返还、激励封顶、官方税费与分账总额守恒。
