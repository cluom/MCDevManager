## Context

共享 Compose 页面已有组件评论读取/回复与 FileKit 文件保存。评论原始字段含 `_id/iid/uid/stars/publish_time`，CSV 导出不含这些完整身份信息。评论接口大区间 count 可能封顶 9999，不能直接以一次请求作为完整名单。

## Goals / Non-Goals

**Goals:** 按条件完整读取当前账号评论，按 UID 去重、等概率抽取，预览并导出原模板两列 CSV；可导入可靠 UID 排除名单；条件及账号变更后旧结果失效。

**Non-Goals:** 不提交赠送，不在报告全部确认前通知，不猜测 app_uid 到评论 uid 的换算，不自动沿用旧跨平台抽奖中的关注/十位编号/黑名单优先规则，不改 iOS 小组件和数据库。

## Decisions

- 纯 Kotlin 领域引擎承载条件校验、最新评价去重、种子抽样和 RFC4180 CSV 编解码，可独立测试。字符串保存所有标识，避免大整数舍入。
- 网络加载器接收可替换的分页函数；单窗口 count 达到 9999 时按日期二分，页数/重复/缺页/总数变化均检查。不使用静默截断后的部分评论抽奖。
- 筛选与抽样分开。每 UID 只保留来源组件中最新一条评价，再匹配星级、标签与关键词。人数不足报错，不重复补位。
- 新页面置于互动管理，沿用主题和自适应宽度；输入更改立即清空结果，长任务可取消，账号会话版本变化立即废弃任务/结果。
- UID 排除 CSV 仅接受明确的玩家uid/uid/game_uid 字段。已知订单导出的玩家ID为 app_uid，可靠映射未确认前拒绝将其当作评论 UID。界面如实显示该限制。
- CSV 固定 UTF-8 BOM、CRLF、表头 `玩家uid,模组id`，列值均为原始数字字符串；使用现有 FileKit 保存器。另可导出不含凭证的抽奖审计 JSON，保留条件、种子和中奖评论依据。
- 本地成功保存 CSV 后记录已导出 UID，但不当作赠送成功；补抽后默认仅导出尚未导出的新中奖者，同时保留完整当前名单重导出入口。
- 结束日期按实测的左闭右开 API 边界转换为次日，使界面日期范围包含结束当天。
- 来源与赠送模组使用当前账号 PE 作品列表的可搜索下拉选择器，展示名称及精确 ID；不再把 ID 当作普通文本输入。列表加载失败可重试，账号变更清空并重新加载，旧请求不得覆盖新账号列表。
- 起止日期使用日历选择弹窗，约束开始不晚于结束且不选未来日期；Material3 日期选择器使用 UTC 日期编码，业务查询仍按北京时间的完整日期处理，避免回显前移一天。
- 通用日期弹窗提供中文 DatePickerFormatter，月份固定为“2026年10月”，选中日期为“2026年10月21日”，不依赖系统语言或修改全局 Locale；仍沿用 UTC 日期转换，星期栏及日期输入模式等其他内置文本不在本次月份显示调整范围内。
- 在当前抽奖结果内本地导入平台赠送报告（玩家uid、模组id、状态、失败原因），按原始 UID + 赠送模组 ID 匹配。只将明确失败的当前中奖者自动补抽；其他模组、非当前中奖者、未知/处理中状态跳过并显示数量。
- 同一 UID 的重复失败合并，一组记录中成功优先；含待处理/未知状态而无成功的冲突记录不自动补抽。保存已确认成功 UID，后续失败报告与手动操作不能替换这些名额。当前匹配记录视为已提交平台，补抽 CSV 仅输出新增补位，未出现在报告中的名额不推断成功或失败。
- 导入报告使用与文件导出相同的结果快照及账号校验；整个补抽请求原子执行，候选不足或 CSV 错误不部分修改结果。重复导入旧失败报告因原 UID 已不在当前名单而不会再次补抽；报告记录与成功 UID 进入审计，不上传文件到服务端。
- 自动回复默认关闭且文案为空，用户填写文案、预览并启用后，只有当前所有中奖 UID 都进入报告确认成功集合才触发；已购替换或未知状态未处理完不提前通知。支持昵称、赠送模组和模组 ID 占位符；展开后的每条回复须符合本地 500 字符限制。
- 回复前重新完整读取源评论并核对原评论 ID、UID、来源模组；已存在开发者回复或源评论不存在时跳过，不主动覆盖。串行低频发送，进度可见，失败停止，账号切换/条件变更/手动停止取消后续请求。
- 新批次使用当前账号 Cookie 快照的独立 HTTP 客户端，后续账号切换不能改变已构建请求的身份；仍在发送前后校验会话。去重记录使用平台本地首选项按账号 + 评论 ID 持久化，先记录待核对再发请求，明确成功后记成功；超时/取消保留待核对且不自动重发。仅明确拒绝项允许用户手动重试，避免响应丢失导致重复通知。不支持多个客户端进程同时执行批量回复。
- 后续维护合入上游 v1.2.9 的密码字段加密与历史明文转换，保留本分支在 users/me 返回后获取 Cookie 快照、保存后绑定账号的流程。密码密钥仍按上游方案保存在应用私有目录，不宣称系统密钥库或全库加密；自动测试使用隔离数据目录，不读取或生成真实账号的密钥。

## Risks / Trade-offs

- [账号切换/登录刷新] → 使用当前账号 ID 与会话代次校验，不把 Cookie 放入输出；任何会话变更要求重新加载。
- [分页过程中评论变化] → 严格完整性校验，失败后重新抓取，不以成功状态展示部分名单。
- [外部排除名单身份混用] → 明确 UID 列和编号范围，拒绝直接导入订单 app_uid；不以零交集宣称无人已购。
- [离线随机复核] → 稳定排序候选 UID、记录种子和候选快照，同一输入同一种子复现结果。

## Migration Plan

无数据库迁移。新增入口可随普通客户端更新发布；回滚本次源代码提交即可，不影响账号、评论和作品。当前回合不覆盖安装目录、不执行实际发放。

## Open Questions

2026-10-21 用户确认暂不依赖编号映射，改为平台判定已购后补抽。结果明确标注未自动校验已购；支持单人和批量指定当前中奖 UID 补抽，仅替换相关位置，保留其他中奖者，并排除所有历史抽中 UID。候选池不足时整个补抽请求失败，不部分修改旧结果。
