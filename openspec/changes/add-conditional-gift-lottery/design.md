## Context

共享 Compose 页面已有组件评论读取/回复与 FileKit 文件保存。评论原始字段含 `_id/iid/uid/stars/publish_time`，CSV 导出不含这些完整身份信息。评论接口大区间 count 可能封顶 9999，不能直接以一次请求作为完整名单。

## Goals / Non-Goals

**Goals:** 按条件完整读取当前账号评论，按 UID 去重、等概率抽取，预览并导出原模板两列 CSV；可导入可靠 UID 排除名单；条件及账号变更后旧结果失效。

**Non-Goals:** 不发布评论，不提交赠送，不猜测 app_uid 到评论 uid 的换算，不自动沿用旧跨平台抽奖中的关注/十位编号/黑名单优先规则，不改 iOS 小组件和数据库。

## Decisions

- 纯 Kotlin 领域引擎承载条件校验、最新评价去重、种子抽样和 RFC4180 CSV 编解码，可独立测试。字符串保存所有标识，避免大整数舍入。
- 网络加载器接收可替换的分页函数；单窗口 count 达到 9999 时按日期二分，页数/重复/缺页/总数变化均检查。不使用静默截断后的部分评论抽奖。
- 筛选与抽样分开。每 UID 只保留来源组件中最新一条评价，再匹配星级、标签与关键词。人数不足报错，不重复补位。
- 新页面置于互动管理，沿用主题和自适应宽度；输入更改立即清空结果，长任务可取消，账号会话版本变化立即废弃任务/结果。
- UID 排除 CSV 仅接受明确的玩家uid/uid/game_uid 字段。已知订单导出的玩家ID为 app_uid，可靠映射未确认前拒绝将其当作评论 UID。界面如实显示该限制。
- CSV 固定 UTF-8 BOM、CRLF、表头 `玩家uid,模组id`，列值均为原始数字字符串；使用现有 FileKit 保存器。另可导出不含凭证的抽奖审计 JSON，保留条件、种子和中奖评论依据。

## Risks / Trade-offs

- [账号切换/登录刷新] → 使用当前账号 ID 与会话代次校验，不把 Cookie 放入输出；任何会话变更要求重新加载。
- [分页过程中评论变化] → 严格完整性校验，失败后重新抓取，不以成功状态展示部分名单。
- [外部排除名单身份混用] → 明确 UID 列和编号范围，拒绝直接导入订单 app_uid；不以零交集宣称无人已购。
- [离线随机复核] → 稳定排序候选 UID、记录种子和候选快照，同一输入同一种子复现结果。

## Migration Plan

无数据库迁移。新增入口可随普通客户端更新发布；回滚本次源代码提交即可，不影响账号、评论和作品。当前回合不覆盖安装目录、不执行实际发放。

## Open Questions

2026-10-21 用户确认暂不依赖编号映射，改为平台判定已购后补抽。结果明确标注未自动校验已购；支持单人和批量指定当前中奖 UID 补抽，仅替换相关位置，保留其他中奖者，并排除所有历史抽中 UID。候选池不足时整个补抽请求失败，不部分修改旧结果。
